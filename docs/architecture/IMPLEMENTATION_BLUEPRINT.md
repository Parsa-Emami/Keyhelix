# KeyHelix implementation blueprint

## Executable proof and concrete layout

Entry point: `cmd/keyhelix/main.go`.

Module map: `internal/{app,provider,auth,vaults,secrets,grants,rotation,audit,health,storage,contracts,security}; apps/web/src/pages`.

Reference vertical slice: Authenticate synthetic owner -> scoped write -> fresh step-up reveal -> grant & revoke other user -> provider outage test -> restore isolated provider from proper recovery material.

For Go repositories use a single root module. Versions are verified and pinned via `go.mod` and `docs/engineering/toolchain-lock.json`.

## Persistence model

OpenBao is authoritative Transit KEK and KV v2 sealed payload backend. Durable local metadata storage is implemented by `internal/storage` (single-writer atomic file storage port with exclusive `LOCK`, `manifests/`, `blobs/`, and `operations/` per ADR-0003; no compulsory external SQL server or SQLite daemon required). No plaintext secret values, raw DEKs, or duplicate ciphertexts are stored in metadata storage.

Constraints enforced in `internal/storage` and `internal/contracts`: opaque ID, owner/scope isolation, schema version, optimistic entity version (CAS), SHA-256 content digests, and per-scope record bounds (`MaxRecords = 256` per scope).

## State and transport

Secret version lifecycle follows provider CAS/version/delete/undelete/destroy (`ACTIVE` -> `DELETED` -> `DESTROYED`). Rotation follows `PLANNED -> REWRAPPING -> VERIFYING -> COMPLETE | FAILED_ROLLBACK` and resumes from durable checkpoints without deleting prior versions.

Go backend-for-frontend (`internal/app`) communicates with the scoped OpenBao HTTP API; the browser never receives long-lived workload or provider admin tokens. BFF routes (`/api/vaults/{vault}/...` and `/api/v1/vaults/{vault}/...`) list metadata and perform explicitly authorized writes, lifecycle actions, grants, rotations, and strict audited reveals.

## Authentication and authorization

OIDC provider (Keycloak in the local profile) + fresh step-up (`prompt=login&max_age=0`) mapped to actual scoped OpenBao authorization (`internal/auth`). Never use an omnipotent app token as a substitute for user authorization. Cookie-authenticated mutations require same-origin verification and `HttpOnly`, `SameSite=Lax`, `Secure` session cookies.

## Configuration without env edits

Runtime configuration is read from `.local-data/runtime.json` (generated by `scripts/providers.mjs` during `npm run setup`). Precedence: explicitly passed `--config` -> safe foundation defaults (`coreReady: false` when launched without `--config`). Existing `.env.example` remains unmodified.

## Development verification workflow

Developer commands (`npm run check`, `go test ./...`, `npm run test:web`, `npm run test:browser`, `npm run test:clone`) verify contracts, Go domain packages, web foundation, and full browser-to-provider workflows.
